# 一个统一的异构专家图网络用于运动会编排：架构、训练与推理

> **体裁说明**：本文件以**论文文体**讲解系统的模型与架构，供需要「一次读懂全局设计」的读者。
> 事实性细节（每一维、每一个命令、每一列）在 `models.md` / `dataflow.md` / `output-to-table.md`。
>
> 版本：2026-10-04　代码：`sports-ai/`（训练与导出）、`sports-backend/.../schedule/ai/`（推理）

## 摘要

运动会编排是一个**多任务、强约束、可判定可行性**的组合优化问题：同一批运动员要分配到时、场、道三类资源，
同时满足兼项避让、场地容量、项目块连续性、行政时段规避等约束，并常常带有「限定 x 天」或「尽可能压缩」的时间目标。
本文描述一套按**难度梯度**组织的四级编排体系（规则 → 启发式 → 元启发式 → 神经网络），
并把顶层收敛为一个**单一模型** `SuperScheduleMoE`：它把十七类编排能力分成

- **11 位任务专家**（项目/道次/球类/淘汰赛/块完整性/兼项/容量/工期/二次编排/裁判/教师），按**节点表征**路由；
- **6 位能力专家**（方案生成/精修/扩散去噪/道次派遣/工期预测/方案判别），按**图级上下文**路由；

并输出七路互补信号（优先级、槽位 logits、任务权重、赛制、工期、道次 logits、方案质量分）。
训练完全**自监督**：标签由与线上同源的贪心装箱算法产生。
实验表明：纯模型链路在魔鬼档位上弱于搜索，因此顶层推理采用
**「模型序当种子 → GA → LNS → 多起点重启」的混合链路**，且最终解在「搜索最优 ∪ 全部种子」中取，
从而获得**单调不劣**的保证。在魔鬼条件（500+ 人 / 15 项目 / 兼项 100%）下，
混合链路相对遗传算法一条龙的未排数由 10.33 降至 9.67（3 seeds）。

**关键词**：组合优化；图神经网络；混合专家；扩散模型；自监督；调度

## 1. 引言

### 1.1 问题

运动会编排要同时回答四个问题：

1. **排哪里**（场地）；
2. **排何时**（哪一天的哪个时段）；
3. **排给谁**（分道 / 分组 / 出场顺序）；
4. **能不能排**（容量、兼项、规避是否满足）。

这四问互相耦合：改了某个项目的时段，可能同时破坏它的**项目块连续性**、
造成若干运动员**兼项撞车**、并把裁判需求推到没有裁判可用的时段。
更麻烦的是，现场需求还包含**时间目标的三态语义**：

| 输入 | 语义 |
|---|---|
| `x ≥ 1` | **硬约束**：必须在 x 天内排完，排不下要如实报不可行 |
| `0` | **不限时间**：只要可行，天数不设目标 |
| `-1` | **尽可能减少**：可行前提下尽量压缩总天数 |

### 1.2 为什么不能只有一个大模型

一个自然的想法是「训练一个端到端模型直接输出赛程」。
本文的实测否定了这一路径：

> **纯 ONNX 链路在魔鬼档（HELL）的「未排数」上比随机基线还差（16.33 vs 15.33）。**

诊断出两个原因：

1. **标签天花板**：训练标签来自贪心解，因此模型的上限就是贪心；而贪心的装箱质量**输给遗传算法**。
   学贪心，永远赢不过搜索。
2. **`slot_logits` 是负资产**：同一实例、同一 GA，喂模型给出的槽位 logits 得 10 个未排；
   喂**全零**只用 7 个。即模型的落桶判断在拖累搜索。

结论是设计层面的：**L4 不应替代 L1–L3，而应站在它们之上**。
本文因此把顶层做成「神经引导的搜索」，而不是「神经替代的搜索」。

### 1.3 贡献

1. 一套**统一表示**（`SuperUnit` / `SuperWindow` / `SuperScenario`）把项目、道次、球类、淘汰赛、
   二次编排、裁判、教师全部落成同一种「单元 × 时段 × 资源」结构（§3）。
2. 一个**异构门控**的超级 MoE（§4.3）：任务专家按节点路由、能力专家按图级上下文路由 ——
   解决「单纯扩大专家数只会摊薄容量」的问题。
3. **七路输出头**与**六个自监督目标**（§4.4–4.5），使单个模型覆盖此前 15 个独立模型的职责。
4. **混合推理链路**（§4.6）：模型序当种子 + GA + LNS + 多起点重启 + 硬约束修复层，
   保证结果**单调不劣**于纯搜索基线。
5. 全部 AI 组件**失败即静默回退规则**，编排永不因 AI 崩溃而失败（§4.7）。

## 2. 相关工作（2026 前沿）

本文的设计与下列 2026 年的工作高度呼应，其中前三项已逐条落到实现里。

### 2.1 可采纳的神经启发式（arXiv:2606.04860）

A\* 类算法保持最优性的前提是启发函数**可采纳**（never overestimate）。
该文指出：用 MSE 训练的代价网络**系统性地高估**，从而破坏可采纳性、剪掉本不该剪的分支。
其修法是**可采纳 Bellman 算子（低估）** + **非对称损失（对高估加重惩罚）** +
**验证集上的事后校准安全偏移**；在 2×2 魔方上减少 83% 的节点扩展且无违例。

**对本系统的意义**：`quality_score` 与 `days_estimate` 正是 MSE 训练的代价型输出。
若把它们当剪枝上界，高估会导致**误剪可行分支**。因此本文在神经引导搜索里
对这两个头做**保守化（低估 + 偏移）**处理，只用于「排序与提示」，不作为硬剪枝依据（§4.6）。

### 2.2 回溯搜索中的验证器（arXiv:2605.22221）

该文指出：用**累积轨迹**做自回归训练的解码器，在「继续 or 回溯」这个判定上有两个失败模式 ——

- **scattered retrieval**：状态特征散落在序列的多个位置上；
- **history entanglement**：预测器条件于**轨迹**而非**状态**，于是两个到达同一状态的不同轨迹会给出不同判定。

修法：**localization**（重写决策块让状态特征局部化）+ **Selective State Attention（固定注意力掩码，
结构化地强制「基于状态」决策，不改数据/目标/参数）**。

**对本系统的意义**：我们的「预测网络」也要在每一步判断「继续 or 回退」。
若直接在一个累积的落位轨迹上做自回归预测，就会踩到同样的坑。
本文采用**状态局部化**的表述（§5.1）：每步只把**当前状态的紧凑特征**喂给预测器，而不喂历史轨迹。

### 2.3 搜索-失败-恢复的训练框架（arXiv:2607.07492, Pyligent）

把推理视为**经过验证的搜索**：验证器标记「生成的延续」与「失败」，把搜索树转成三种动作的监督目标 ——
**继续 / 完成 / 回溯**，并可选给出被放弃分支的总结。相比只模仿成功路径的监督微调，
在隐藏图上解决率提升 72.7 个百分点。

**对本系统的意义**：直接给出了「回退」应有的标签结构。本文的 `PredictiveSearch`
以同样的三动作结构组织回退（§5.2），并记录每次回退原因（容量 / 兼项 / 块断裂 / 无可用槽）。

### 2.4 双层优化与 3R 恢复（arXiv:2606.06877）

把「神经打分器」放在**上层**、把「符号规划器」放在下层，下层在上层打分**剪枝后的空间**里求解；
这带来 **exposure bias**（训练在全空间、部署在自剪枝空间）。
其修法是在下层引入 **3R：Repair / Restart / Rollback**，为上层提供可靠反馈。
结果：失败率 −80%，规划时间 −57%。

**对本系统的意义**：这正是我们「模型当种子 + 算法精修」的严格形式化。
我们的 `repair` 层对应 **Repair**，多起点重启对应 **Restart**，
按决策点回退对应 **Rollback**（§5.3）。

### 2.5 与本文的一处工程性分歧

上述工作大多在**同构**专家上做研究。而本文的实测发现：把专家从 11 扩到 17 若保持同构，
`load_balancing_loss` 会把使用率强行拉平均，但**每个专家学到的几乎是同一件事**。
因此本文引入**输入依赖不同**的异构门控（§4.3）—— 这比「让专家带不同 hop 范围」更直接地制造分工。

## 3. 问题形式化

### 3.1 统一表示

一个**赛会**表示为三元组 $(\mathcal{U}, \mathcal{W}, g)$：

- **单元** $u \in \mathcal{U}$：$u = (k, v, p, d, \iota, h, A, G, \tau, \rho, s)$
  其中 $v$ 场地、$p$ 并发池、$d$ 时长、$\iota$ 最小间隔、$h$ 道次容量、$A$ 运动员集合、
  $G$ 项目块键、$\tau$ 任务类型、$\rho$ 晋级关系、$s$ 阶段；
- **窗口** $w \in \mathcal{W}$：$w = (\text{day}, \text{idx}, v, p, c)$，$c$ 为该时段该场地的容量（分钟）；
- **时间目标** $g$：三态（§1.1）。

**时间桶**定义为 $b = (\text{day}, \text{idx})$ —— **同一桶内多场地并行**。
这是后续所有「槽位」语义的基础：一个槽 = 一个时间桶。

### 3.2 约束

| 约束 | 类型 | 形式化 |
|---|---|---|
| 兼项避让 | 硬 | $\forall a,\ |\{u : a \in A_u \wedge b_u = b'\}|$ 满足最小间隔 |
| 场地容量 | 硬 | $\sum_{u \in b, v} (d_u + \iota_u) \le c_{b,v}$ |
| 场地独占 | 硬 | 同一窗口同场地不得重复占用 |
| 项目块连续 | **软** | 同一 $G$ 的单元跨天即罚 |
| 行政规避 | 硬 | 被保护的 `(day, time)` 区间不生成窗口 |
| 时间目标 | 硬/软 | $g \ge 1$ 为硬上界；$g < 0$ 为软目标（跨天惩罚 ×5） |

> **项目块连续刻意用软约束**：容量客观不足时，硬约束会把求解器直接逼到无解；
> 而现场要的是「给最不碎片的方案 + 告诉我差多少」。

### 3.3 目标

主目标是**未排单元数**最小；但仅此一项在装箱问题下贪心就是强基线，
因此对比还需看**兼项撞车 / 道次撞车 / 碎块度 / 工期**四项。
本文的评测同时报告这五项（见 `benchmarks.md`）。

## 4. 方法：统一编排超级模型

### 4.1 编码（输入表示）

节点特征 $\mathbf{x}_i \in \mathbb{R}^{20}$，分五组：

| 组 | 维 | 内容 |
|---|---|---|
| 规模 | 0–4 | 单元数占比 / 人数 / 相对最挤单元 / 时长占比 / 场地数 |
| 需求 | 5–8 | 装箱紧张度 $(d+\iota)/c$ / 容量余量 / 冲突暴露 / 兼项占比 |
| 约束 | 9–12 | 是否项目块 / 块内规模 / 是否道次 / heat 容量 |
| 时间 | 13–15 | **时间目标三态** / 天数占比 / stage |
| 赛制 | 16–19 | group / round_robin / knockout / hybrid 的 one-hot |

边集为**八类约束**的分类型邻接张量 $\mathbf{A} \in \mathbb{R}^{8 \times N \times N}$：
兼项 / 项目块 / 场地 / 并发池 / 装箱间隔 / 道次 / 晋级 / 同队。
另配 $\mathbf{m} \in \{0,1\}^{8}$ 的边型掩码（区分「不存在」与「值为 0」）。

图级（实例级）特征 $\mathbf{g} \in \mathbb{R}^{8}$：冲突密度 / 单元规模 / **有效场地数** /
天数 / 时间目标 / **并行度** / **填充率** / 块压力。

> 这三段在**训练侧（Python）与推理侧（Java）逐位对齐**，由逐位断言的单测钉死。
> 曾有两次真实错位：一处是两端口径不同（场地数取「场地总数」vs「有窗口的场地数」；
> 并行度按「窗口条数」vs「时段内不同场地数」；填充率因两个 `int` 相除被截断成 0）；
> 另一处是 **Python 用一行 `feat[i,19] = ...` 覆盖了 Java 从未实现的第 19 维**，
> 使训练与推理对同一维语义不同且不报错。二者均已修正并加断言。

### 4.2 主干：四路混合

模型内部同时含四种归纳偏置（**不是四个模型的拼装**）：

| 路 | 部件 | 回答的问题 |
|---|---|---|
| **GNN** | `_ExpertStep` 的边级 + 节点级双注意力 | 谁和谁冲突、消息怎么传 |
| **CNN** | `LocalConvBlock`（`Conv1d`, k=5 ×3） | **项目块的局部连续性**（排班网格上的空间局部性） |
| **Diffusion** | `DiffusionDecoder`（8 步余弦调度） | 从噪声生成 / 迭代精修分配矩阵 |
| **MoE** | `MultiGateMoE` | 不同能力的**分工与融合** |

**设计约束（工程性，但直接决定正确性）**：所有 reshape 必须从 `x.shape` 现算，
不得出现 `int(sqrt(n))` 这类 Python 整数运算 —— 它们在 ONNX 导出时会被**常量折叠**成
导出那一刻的 $B, N$，导致服务端喂别的规模时崩溃，而异常会被 `catch (Throwable)` 吞掉，
表现为「AI 没生效但也不报错」。因此：

- 自注意力**手写**（`HeadAttention`）而不用 `nn.MultiheadAttention`；
- CNN 用 `Conv1d` 而不用 `Conv2d`；
- 边型缺席用**张量门控**而不用 `if float(...) == 0: continue`。

### 4.3 异构门控（核心）

专家池分两层，**路由粒度不同**：

$$\mathbf{q}^{\text{task}} = \underbrace{\mathbf{h}\mathbf{E}^\top}_{\text{节点}}
+ \underbrace{\mathbf{c}\mathbf{E}^\top}_{\text{结构上下文}}
+ \underbrace{\tfrac{1}{|\mathcal{G}|}\sum_{g \in \mathcal{G}} g(\mathbf{h})}_{\text{多门平均}},
\qquad
\mathbf{q}^{\text{cap}} = \underbrace{\mathbf{c}_{:1}\mathbf{E}^{\top}}_{\text{仅图级}}$$

于是**同一实例内所有节点对能力专家的权重相同** —— 能力专家成为**实例级**专家。
门控取 softmax 后按节点加权汇聚各专家输出。

**动机（实测）**：任务专家回答「**这个单元**怎么排」，能力专家回答
「**这个赛会**需要多少生成/精修/派遣/预测」。若两者同构，扩专家只会摊薄容量。

**负载均衡**：$\mathcal{L}_{\text{lb}} = E \cdot \sum_e \bar{p}_e^2 + \mathcal{H}$，
否则 MoE 会退化成「只有 1–2 个专家干活」而 loss 照常下降。

### 4.4 十七位专家与七路输出

| 层 | 专家 | 语义 |
|---|---|---|
| 任务 | 0–10 | 项目 / 道次 / 球类 / 淘汰赛 / 块完整性 / 兼项 / 容量 / 工期 / 二次编排 / 裁判 / 教师 |
| 能力 | 11–16 | 方案生成 / 精修 / 扩散去噪 / 道次派遣 / 工期预测 / 方案判别 |

| # | 输出 | 形状 | 作用 |
|---|---|---|---|
| 0 | `priority` | $[B,N]$ | 调度优先级（当求解器初始序） |
| 1 | `slot_logits` | $[B,N,16]$ | 时间槽分配 |
| 2 | `task_probs` | $[B,17]$ | 专家门控权重（诊断专家是否塌缩） |
| 3 | `format_logits` | $[B,4]$ | 球类赛制推荐 |
| 4 | `days_estimate` | $[B,1]$ | 工期预测 |
| 5 | `lane_logits` | $[B,N,16]$ | 道次派遣 |
| 6 | `quality_score` | $[B,1]$ | 方案质量分（Sigmoid） |

> **生成/精修/扩散复用 `slot_logits`**：三者的输出本质都是「单元 → 资源」的分配矩阵，
> 而 `DiffusionDecoder` 本身就是「从噪声生成 → 迭代精修」的过程。
> 真正需要独立输出的是派遣（道次语义）、预测（标量工期）与判别（质量分）。

### 4.5 自监督训练

数据由**场景生成器**产出（五档，覆盖魔鬼条件：500+ 人 / 15+ 项目 / 兼项 1–3 项；
以及 300 人 / 10 项目 / 限 2–3 天），标签由与评测/线上**同源**的贪心装箱（MSBF + best-fit）产生。

$$\mathcal{L} = \underbrace{\mathcal{L}_{\text{pri}}}_{\text{优先级 MSE}}
+ \underbrace{\mathcal{L}_{\text{slot}}}_{\text{槽位 MSE}}
+ \lambda_{\text{lb}}\mathcal{L}_{\text{lb}}
+ 0.3\left(\mathcal{L}_{\text{fmt}} + \mathcal{L}_{\text{lane}} + \mathcal{L}_{\text{days}} + \mathcal{L}_{\text{qual}}\right)$$

其中

| 项 | 目标 | 说明 |
|---|---|---|
| $\mathcal{L}_{\text{lane}}$ | 与 `slot` 相同但**按 `lane_mask` 加权** | 只有径赛/批次单元参与（田赛/球类无道可分） |
| $\mathcal{L}_{\text{days}}$ | 贪心落位**实际跨天数** | 覆盖原 forecast 模型 |
| $\mathcal{L}_{\text{qual}}$ | $1/(1+\mathrm{CV})$，CV = 各桶负载变异系数 | 负载越均衡方案越优 —— 覆盖原 GAN 判别器 |

**两条必须记住的训练纪律**：

1. **标签必须与输入同源**。早期 slot 标签用 `hash(venue) % n_slots`，与真实落位无关，
   且 Python 字符串 hash 带随机化（每进程不同）—— 那是比噪声更糟的**标签抖动**：loss 下降、指标好看、模型什么都没学到。
2. **深度必须配预算**。参数量近似 $\propto \text{hidden}^2 \times \text{depth}$，
   因此宽度按平方、深度按线性放大训练轮数。本模型曾因只训 5 轮而
   `val_loss` 1.136 / `pri_mse` 0.0168，被误读成「深层不如浅层」；补训后追平。
   该规则已实现为 `sports_ai/budget.py` 并接入全部训练脚本。

### 4.6 混合推理链路（L4）

```
业务对象 ──编码──▶ 张量 ──▶ super_moe ──▶ Advice
                                            │ priority 当**初始序**
                                            ▼
        启发式（L2 紧度构造序）→ GA（OX 交叉 + 交换/插入变异 + 精英）
                              → LNS（破坏-重建，**按 MC Dropout 方差优先破坏**）
                              → 多起点重启（停滞则用紧度构造序重新播种）
                                            │
                                            ▼
                        硬约束修复层 Repair（容量 / 兼项）→ blocked 诚实上报
                                            │
                                            ▼
                        最终解 = argmin over（搜索最优 ∪ 全部种子）
```

**单调不劣保证**：初始种群包含「模型序」与「启发式序」两个种子，且最终解在二者与搜索最优中取 ——
因此链路**只可能变好，不可能变差**。

**为何用 MC Dropout 指导破坏**：Generative LNS（2026）指出「**不稳定即信息**」——
去噪轨迹中预测剧烈波动的变量正指向结构歧义/高耦合，优先修复收益最大。
ONNX 拿不到中间去噪步，故用 5 次前向的预测方差作廉价代理。

### 4.7 降级

所有 AI 组件（15 个模型、7 个服务）在**模型缺失 / 规模超限 / 编码降级 / 推理异常**时
返回 `Optional.empty()`，上层继续走 L1–L3。**代价**是「AI 没生效」不报错，
因此必须配合主动可观测：`/api/ai/status`、响应里的 `superMoeLoaded`、启动日志
`超级编排模型已就绪: super_moe.onnx (jar 内)`。

## 5. 面向「预测 + 回退」的神经引导搜索

§2 的 2026 工作给出了「启发式 + 搜索 + 预测 + 回退」的理论骨架。本节给出本系统的对应设计。

### 5.1 状态局部化的预测器（对应 §2.2）

**要解决的问题**：在「逐个确定单元落位」的过程中，每一步都需判断
「当前选择能否走通」。若把**累积的决策轨迹**喂给预测器，会出现
*scattered retrieval* 与 *history entanglement*（两个到达同一状态的轨迹给出不同判断）。

**设计**：预测器只在**当前状态的紧凑特征**上做判断，不喂轨迹。

$$\hat{y}_t = f_\theta\big(\ \mathbf{s}_t\ \big),\qquad
\mathbf{s}_t = \big[\ \text{剩余容量分布},\ \text{未排单元的兼项暴露},\ \text{块断裂计数},\ \text{剩余天数预算}\ \big]$$

**实现要点**：`s_t` 只包含**从当前状态可算**的量，不含「历史走了哪条路」。
这等价于 SSA 想要的结构性隔离，但不需要改训练目标/参数 —— 靠**接口约束**达成
（同样的思路，更低的成本）。

### 5.2 三动作回退（对应 §2.3）

把搜索树的节点动作定为三种（与 Pyligent 一致）：

| 动作 | 触发条件 | 处理 |
|---|---|---|
| **继续** | 预测可行 且 实际校验通过 | 推进到下一单元 |
| **完成** | 所有单元已排 且 全局校验通过 | 提交方案 |
| **回溯** | 预测不可行 或 实际校验失败 | 撤销最近一次决策，穷尽该点的其余候选 |

**与「先预测后校验」的关系**：预测器只用来**排序候选**（先试最可能成功的），
**是否可行由确定性校验器裁决**（容量 / 兼项 / 块连续）。这样预测错了也只是多试几次，
不会产生错误结论 —— 这是「可回退」能成立的**前提**。

### 5.3 3R 恢复（对应 §2.4）

| R | 在本系统中的对应 | 触发 |
|---|---|---|
| **Repair** | `solve/repair.py`：只修「能不能」（容量超载 → 重放；兼项撞车 → 换槽） | 方案局部不可行 |
| **Restart** | GA 多起点重启：停滞则用**紧度构造序**（承载下界信息）重新播种 | 连续多代无改进 |
| **Rollback** | 决策点回退：撤销最近一次落位并穷举其余候选 | 该子树被判定无解 |

修不动时**诚实上报 `blocked`**（而不是返回一个假装可行的方案）。

### 5.4 可采纳性保护（对应 §2.1）

`quality_score` 与 `days_estimate` 都是 MSE 训练，**倾向高估**。
若用它们剪枝，会误剪可行分支。因此本文：

1. 训练侧对这两个头引入**非对称损失**（对高估加重惩罚），使其倾向**低估**；
2. 推理侧对预测值施加**保守偏移**（`value − δ`，δ 由验证集校准）；
3. 并且**只用于排序与提示，绝不作为可行性的判决依据** ——
   可行性永远由确定性校验器裁决。

> 这三条是「预测网络可以放心用」的完整条件。缺任何一条，
> 高估都会以「莫名其妙剪掉了可行解」的形式表现出来，且极难定位。

## 6. 实验

详见 `benchmarks.md`。摘要：

| 口径 | HELL（魔鬼） | REGULAR | BLOCK | LANE | TEAM |
|---|---|---|---|---|---|
| random | 15.33 | 2.67 | 10.67 | 1.33 | 1.33 |
| greedy | 16.00 | 4.00 | 12.67 | 2.33 | 1.33 |
| **GA 一条龙** | 10.33 | 1.33 | 7.67 | 1.00 | 1.33 |
| 纯 ONNX | 16.33 | 3.67 | 11.00 | 2.33 | 1.33 |
| **本文混合链路** | **9.67** | **1.33** | **7.67** | **1.00** | **1.33** |

（单位：未排单元数，3 seeds 平均）

三条结论：

1. **纯模型链路弱于随机** → 印证 §1.2：标签天花板 + `slot_logits` 误导落桶；
2. **混合链路在魔鬼档严格胜出**（9.67 < 10.33），其余档持平；
3. **其余档的持平是「接近下界」而非「搜索不足」**：这些实例的未排数已是 1.0/1.33，
   接近 0 下界。GA 解码次数从 252 加到 9600，HELL 仅从 7 降到 6 —— 堆预算无益。
   后续已换用「兼项撞 / 道次撞 / 碎块 / 工期」的**加权代价口径**（`metrics.py` / `PlanCost`）：
   HELL 的差距由「未排 10.0 vs 10.33」放大为「加权 10040 vs 10380」且可分解；
   其余四档在所有模式下仍并列 —— 已定位为**结构性原因**（混合链路的最终解取
   「搜索最优 ∪ 全部种子」，而 GA 就是它的种子之一 → 只可能 ≤ GA），
   即剩余差距要靠**抬高标签天花板**（RSI）而不是换指标（`benchmarks.md` §11.1）。

## 7. 讨论与局限

1. ~~**代价口径**：当前主指标是未排数，在装箱类问题上区分度有限（§6）。
   下一步应引入加权代价。~~ **已引入**（`sports_ai/metrics.py` + Java `PlanCost`）：
   未排 / 兼项撞 / 超占（按分钟）/ 道次撞 / 碎块 / 工期超限。
   实测确认了两件事：① 它确实把魔鬼档的差距放大并可分解；
   ② 它同时**排除了**「四档持平 = 指标太粗」这个假说 —— 剩余持平是结构性的。
   顺带发现默认场景生成器让「工期超限」恒为 0（窗口天数恰好等于 `days_limit`），
   已补 `extra_days` / `--extra-days` 口径使其真正触发（`benchmarks.md` §11.1）。
2. **预测头的偏差**：`quality_score` 尚未做非对称训练与校准，目前只当提示用（§5.4）。
3. **合并模型的训练量**：17 专家模型的推荐预算尚未跑满（见 `audit.md` 缺口清单）；
   当前权重是**热启动续训**的结果，指标仍在改善。
4. **能力专家的可解释性**：6 位能力专家的专家级语义（哪几位真正对应「生成/精修」）
   目前只有门控统计（`task_probs`）支持，尚无因果级验证。
5. **`constraint_gnn` / `scheme_diffusion` / `forecast_*`** 的职责已被超级模型覆盖，
   但独立模型仍在仓库内维护（作为对照与回退）。

## 8. 结论

本文把运动会编排的四档难度梯度收敛到「顶层一个模型」：
一个 **17 位异构专家的图-卷积-扩散混合网络**，输出七路互补信号，
覆盖项目 / 道次（含接力）/ 球类四赛制 / 淘汰赛 / 混合 / 兼项 / 块连续 / 二次编排 / 裁判 / 教师共十七类能力。
训练全自监督，标签与线上同源；推理走「神经引导搜索 + 硬约束修复 + 多起点重启 + 决策点回退」，
并获得**单调不劣**保证。工程上确立了四条硬纪律：
**双端逐位对齐**、**导出必须 `dynamo=False` 且验动态 N**、**深度必须配预算**、
**AI 失败静默回退但不静默失察**。

## 附录 C：四条硬纪律

1. **双端逐位对齐**：改任何一维必须同步 Python / Java / ONNX 输入维度，并有单测钉死。
2. **导出纪律**：必须 `dynamo=False`；导出后用 $N \in \{1,3,4,12,24,47\}$ 验动态轴。
3. **预算纪律**：改模型默认维度必须同步改训练预算（`budget.py` 会 WARN）。
4. **回退纪律**：AI 失败一律回退规则；但必须有主动可观测手段，否则「没生效」会静默。
