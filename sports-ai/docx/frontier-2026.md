## 1. 检索到的四篇核心工作

### 1.1 可采纳的神经启发式 — arXiv:2606.04860（2026-06）

**核心结论**

- A\* 类算法保持**最优性**的前提是启发函数**可采纳**（never overestimate 真实剩余代价）；
- 用 MSE 训练代价网络会**系统性地高估**，从而破坏可采纳性、**剪掉本不该剪的分支**；
- 修法三件套：**① 可采纳 Bellman 算子（低估）** + **② 非对称损失（对高估加重惩罚）**
  + **③ 验证集上的事后校准安全偏移**；
- 效果：2×2 魔方节点扩展 −83%，无一次可采纳性违例。

**对我们的意义**

`days_estimate` 与 `quality_score` 正是**MSE 训练的代价型输出**。
此前我们把它们当"参考"，但如果**拿它们剪枝**，高估会以
「莫名其妙剪掉了可行解」的形式出现，而且**不报错**——这是最难查的一类。

**已落地**（`sports_ai/plan/hybrid_search.py`）

| 论文要素 | 我们的实现 |
|---|---|
| 低估取向 | `CompletionPredictor.w_over = 4.0 > w_under = 1.0`（对「预测能完成、实际不能」重罚） |
| 校准偏移 | `CompletionPredictor.calibrate(feats, labels, quantile=1.0)` → 取最大高估量作 `calib_delta` |
| 可采纳性判据 | `is_admissible(estimate, true_cost)`，并由单测逐样本断言校准后无违例 |
| **只排序不剪枝** | `plan_predictive` 里预测值只进 `score()` 排序；可行性由 `verify_slot_map` **确定性裁决** |

> 这最后一条是我们比论文更保守的地方：论文用可采纳启发式**指导剪枝**，
> 我们进一步规定**预测永不参与剪枝判决** —— 多花一点搜索，换「不可能因为预测错而丢解」。

### 1.2 回溯搜索中的验证器 — arXiv:2605.22221（2026-05）

**核心结论**

用**累积轨迹**做自回归训练的解码器，在「继续 or 回溯」判定上有两个失败模式：

- **scattered retrieval**：状态特征散落在序列的多个位置，模型难以取用；
- **history entanglement**：预测器条件于**轨迹**而非**状态** —— 两条到达同一状态的不同轨迹会给出**不同**判定。

修法：**localization**（重写决策块让状态特征局部化）+ **Selective State Attention**
（固定注意力掩码，结构化强制「基于状态」决策，不改数据/目标/参数）。
另给出**免重训方案**：推理时清空上下文。

**对我们的意义**

我们的「预测下一步能不能走通」如果直接吃落位轨迹，会踩同样的坑。

**已落地**

采用论文的**免重训那条路**（推理时隔离），但做得更彻底：**从接口上就不给历史**。

```python
# StateView.feat() 只含「从当前状态可算」的量：
#   填充率 / 容量余量 / 剩余兼项暴露 / 块断裂度 / 工期占预算比 /
#   剩余未排比例 / 负载离散度 / 当前是否仍可能可行
```

单测 `test_state_features_depend_only_on_state_not_history` 直接钉住
「同一状态 → 逐位相同特征」。这是**结构性隔离**，不依赖注意力掩码，也不需要重训。

### 1.3 搜索-失败-恢复的训练框架 — arXiv:2607.07492（2026-07，Pyligent）

**核心结论**

把推理视为**经过验证的搜索**：验证器标记生成的延续与失败，
把搜索树转成三种动作的监督目标 —— **继续 / 完成 / 回溯**，并可选给出放弃分支的总结。
相比只模仿成功路径的监督微调，在隐藏图上解决率 **+72.7 个百分点**。

**对我们的意义**

直接给出「回退」应有的**标签结构**：**失败分支同样是监督信号**。

**已落地**

| 论文要素 | 我们的实现 |
|---|---|
| 三动作 | `SearchLog.continues / completes / backtracks`，外加 `repairs / restarts / rollbacks` |
| 回溯原因可诊断 | `SearchLog.backtrack_reasons`（无候选 / 完成校验失败 / 触达上限） |
| 失败分支也是监督信号 | `collect_training_pairs()` 用 DFS 跑**验证搜索树**，把每个状态的「最终能否完成」当标签（含大量 0） |

单测 `test_collect_training_pairs_marks_infeasible_states` 断言标签里**必须出现 0** ——
如果只会收集成功样本，这条会失败。

### 1.4 双层优化与 3R 恢复 — arXiv:2606.06877（2026-06）

**核心结论**

把神经打分器放**上层**、把符号规划放**下层**（在下层于上层打分剪枝后的空间里求解），
会带来 **exposure bias**（训练在全空间、部署在自剪枝空间）。
修法是在下层引入 **3R：Repair / Restart / Rollback** 提供可靠反馈。
结果：失败率 **−80%**，规划时间 **−57%**。

**对我们的意义**

这正是「模型当种子 + 算法精修」的**严格形式化**。我们已有全部三个 R，但此前**没有统一定义**。

**已落地**

| R | 我们的对应 | 触发条件 |
|---|---|---|
| **Repair** | `solve/repair.py` + `plan/_try_repair` | 方案局部不可行（容量超载 / 兼项撞车）；**只修「能不能」，不修「好不好」** |
| **Restart** | GA 多起点重启 + `plan_predictive(max_restarts=…)` | 连续无改进 / 整趟失败；**换序时保留启发式信息**（不纯随机） |
| **Rollback** | 决策点回退（`dfs` 里撤销最近一次落位并穷举其余候选） | 该子树被判定无解 |

三个 R 的顺序是 **先 Repair、再 Rollback、最后 Restart** —— 越便宜的越先试。
单测里专门构造了「Repair 修不动 → 必须 Rollback」的场景（`b` 只有一个候选槽），
以及「首趟必败 → Restart 计数增加」的场景。

## 3. 已实现的架构升级：启发式 + 搜索网络 + 预测网络（可回退）

新模块 `sports_ai/plan/`（`hybrid_search.py`），把用户要的三件事组装成一条链：

```
启发式序（MSBF 紧度：候选越少越先排 —— 确定性，不依赖模型）
   │
   ├─ 搜索神经网络：neural_prior(unit, slot)   ── 只用模型的 slot_logits 排序候选
   ├─ 预测网络：CompletionPredictor(state)     ── 只判断「当前状态能否排完」
   │
   ▼
候选按 score = neural_prior + 0.5×predictor(state) 排序
   │  ⚠️ 预测值经 conservative_value 保守化（低估 + 校准偏移）
   ▼
逐单元落位 → 校验器裁决（容量 / 兼项 / 场地是否开）
   │  不通过 → ① Repair（换槽）→ ② Rollback（回溯）→ ③ Restart（换序）
   ▼
PlanResult{ slot_of, feasible, violations, blocked, log, value }
```

### 3.1 关键设计决策

| 决策 | 理由 |
|---|---|
| 启发式序**不依赖模型** | 模型缺失 / 旧版 onnx 时仍能工作；模型只用来**改进顺序**，不决定可行性 |
| 预测值**只排序、不剪枝** | 唯一能保证「预测错了也不会丢解」的做法（`verify_slot_map` 独占裁决权） |
| 校验器**把「场地未开」判不可行** | 早期把 `caps` 缺失当「容量无限」，会让方案看起来可行、实际排不进去 |
| Repair 优先于 Rollback | 换槽的成本远低于整条路径回退（与论文的 3R 顺序一致） |
| Restart **保留启发式信息** | 纯随机重启会丢掉「紧的单元先排」这个下界信息，等于从零开始 |
| 状态特征**只含当前状态** | 结构性避免 history entanglement，不依赖注意力改造与重训 |
| 失败分支**也进训练集** | 只学成功路径的模型学不会「何时该回退」 |

### 3.2 实测（真实场景，seed=7）

用生成器的五档真实场景（槽 = 时间桶；容量键 = (槽, 场地)）跑 `plan_predictive`：

| 档 | 单元数 | 槽数 | 可行 | 未排 | 回退 | 修复 | 重启 | 耗时 |
|---|---|---|---|---|---|---|---|---|
| HELL（魔鬼） | 53 | 15 | ✗ | **5** | 97 | 3 | 2 | 0.06s |
| REGULAR | 49 | 9 | ✗ | **1** | 24 | 3 | 2 | 0.03s |
| BLOCK | 77 | 12 | **✓** | **0** | 21 | 0 | 0 | 0.03s |
| LANE | 34 | 8 | **✓** | **0** | 5 | 0 | 0 | 0.03s |
| TEAM | 35 | 12 | **✓** | **0** | 0 | 0 | 0 | 0.03s |

**三档完全解出**（BLOCK / LANE / TEAM，未排 0），HELL 与 REGULAR 剩少量未排 ——
并且**零容量/兼项违规**（`violations` 里只剩「未排」，没有任何非法落位）。

**为什么 HELL 排不完是「诚实」而不是「失败」**：把那几个单元逐个查过，
它们的场地容量已被前序单元占满（区间求和恰好卡死），让位链加深到 8 层也无法腾出空间。
继续加深只会空转到回退上限（depth=8 时回退 20027 次、耗时 5.4s 仍未改善）。
此时**如实报「未排 5」比返回一个超容方案有用得多** —— 后者在现场意味着"赛程打出来但排不进去"。

⚠️ **口径提醒**：上表的「未排」是**本模块自洽口径**（每 (槽, 场地) 的分钟容量求和），
与 `benchmarks.md` 里 GA/模型链路的「未排」不是同一套解码口径，**不可直接跨表比较**。
这里要说明的是**规划层本身能工作**，而不是「超过了 GA」。

### 3.3 预测器实测（可采纳性保护生效）

以 LANE 场景跑 `collect_training_pairs` 收标签（蒙特卡洛式验证搜索树）：

```
状态样本 69 个，标签分布 [53 个"不可完成", 16 个"可完成"]
欠训（1 epoch）时：loss=0.836，高估样本数 > 0        ← 目标态"乐观"确实存在
校准（quantile=1.0）：delta = 0.4069
校准后：可采纳性违例 = 0 / 69                        ← 与 arXiv:2606.04860 的结论一致
```

这正好复现了论文的因果链：**MSE 训练 → 乐观 → 校准偏移 → 零违例**。
只有走到这一步，预测值才敢参与「先试哪条分支」的排序。

### 3.4 开发过程中修掉的三个真问题

写这个原型时暴露出的都不是"新功能缺失"，而是**既有数据的结构性问题**：

| 问题 | 症状 | 修法 |
|---|---|---|
| **影子任务窗口容量写死** | `add_shadow_tasks` 给裁判/教师单元的 V0 窗口容量写死 `max(120, w0.capacity//2)`，而它们实际需求常达 200+ 分钟 → **客观装不下**；此前靠 `greedy_targets` 的「放不下就退到最大桶」兜住，但那产出的是**超容标签**：模型学到「超容也算排下了」，而确定性校验器会判它不可行 —— 训练与部署的可行性口径分叉 | 容量按影子任务**实际需求 ×1.2** 分配 |
| **影子单元随机共享运动员 ID** | 裁判组用 `rng.randint(1000,1011)` 取 ID，两个裁判组可能撞同一个 ID；而所有影子单元又被强制进**同一个 V0 槽** → 「同槽同人」让它们**永远排不下**（每次固定 2~3 个钉子户） | 改为按序号取唯一 ID（它们本来就是不同的裁判组/教师） |
| **搜索的"排序"与"剪枝"混淆** | 早期只在**候选排序**里给兼项冲突打 `-inf`，没有在落子时剪枝 → 搜索反复生成「同槽同人」的**完整方案**、校验失败、修复也修不动、回退后又走同一条确定性路径 —— 实测空转到 2 万次回退，**一个单元都没排下** | 把兼项提到 `_local_ok`（前向检查）；并且 ejection 让位后**必须重做一次前向检查**才能提交（第一版直接塞进去，引入了"超容 180>179"与"兼项撞 REF0/REF2"却对外报 blocked=[]） |

> 最后一条是最值得记的：**「只排序」和「只剪枝」都是错的**。
> 正确的分工是 —— **可行性判定（剪枝）必须确定性且尽早**；
> **模型与预测只影响顺序**。混在一起就会出现「看起来排下了，其实方案非法」。

### 3.5 可诊断输出

`PlanResult.log` 明确区分六个计数，用于回答「这次到底回退了几次、为什么」：

```json
{"continues": 37, "completes": 1, "backtracks": 3, "repairs": 2,
 "restarts": 1, "rollbacks": 3,
 "reasons": ["完成校验失败:兼项撞:7@0(a,b)", "无候选:REF2"]}
```

> 这一条本身就是对旧设计的改进：**原来「方案没排好」只有一个结果，没有过程**。
> 现在能回答「是容量不够、兼项互斥，还是候选集本身为空」。

## 5. 检索与判断的共同教训

1. **「不确定即信息」**（Generative LNS）：模型最没把握的地方，正是结构歧义/高耦合所在，
   优先处理收益最大 —— 我们已把它用在 LNS 破坏集（MC Dropout 方差）。
2. **「高估的代价远大于低估」**：预测只要参与剪枝，就必须先做保守化与校准。
3. **「失败分支要进训练集」**：只模仿成功路径的模型，学不会什么时候该放弃。
4. **「先判适用性，再判实现」**：检索结果里能落到具体数据列/决策点的才做，
   其余写进文档即可 —— 否则就是拿摘要当成果。
