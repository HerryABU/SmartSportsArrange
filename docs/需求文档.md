# 1. 项目概述

## 1.1 项目背景

学校运动会组织过程中，涉及多个角色（体育老师、班主任、学生），存在以下痛点：

- **体育老师**：需要统一管理所有项目、编排、成绩统计，工作量大且容易出错
- **班主任**：需要为本班学生报名、查看本班成绩，缺乏便捷的自助工具
- **学生**：希望查看自己的比赛安排和成绩，信息获取渠道不畅
- **数据分散**：报名表、成绩单散落在 Excel 文件中，难以统一管理和追溯
- **编排依赖人工**：道次分配、分组排布靠经验手工完成，容易出现同班同跑道、跨年级混排等问题
- **成绩统计繁琐**：排名计算、积分累计、团体总分汇总需要大量人工计算

## 1.2 项目目标

开发一套完整的运动会智能编排系统，实现以下核心目标：

| 目标 | 说明 |
|------|------|
| **多角色端** | 体育老师端（管理）、班主任端（报名）、学生端（查看），各司其职 |
| **私有部署** | 学校内网部署，数据安全可控，不依赖外网 |
| **自定义项目** | 项目管理端可灵活配置比赛项目，预设常用项目模板 |
| **自动化编排** | 满足禁止跨年级、同班尽量不同道、同班尽量不同组等约束 |
| **全流程管理** | 报名 → 编排 → 成绩 → 排名 → 导出，闭环管理 |
| **数据导入导出** | 支持 Excel 批量导入导出，保留现有工作习惯 |

## 1.3 项目范围

### 包含范围

- 基础数据管理（班级、运动员、项目）
- 报名管理（班主任报名、体育老师审核）
- 智能编排（道次分配、分组）
- 成绩录入与管理
- 排名与积分统计
- Excel 导入导出（支持别名映射）
- 多端界面（体育老师端、班主任端、学生端）
- 报表生成与导出（秩序册、成绩册）

### 不包含范围

- 电子计时硬件对接（预留接口，后续版本）
- 移动端 APP（提供响应式 Web 即可）
- 在线直播/实时成绩推送（后续版本）
- 人脸识别/指纹签到（后续版本）

|--------|------|------|
| 组别列表 | 列表 | 每个组的信息（组号、跑道分配） |
| 道次分配 | 二维数组 | 组×跑道的运动员分配矩阵 |
| 编排统计 | 对象 | 总人数、组数、每组人数、空跑道数 |
| 警告信息 | 列表 | 无法满足的约束警告（不阻断编排） |
| 执行时间 | 毫秒 | 编排算法耗时 |

### 4.6.3 编排算法流程

```
Step 1: 数据准备
  ├── 获取该项目已审核通过的所有报名运动员
  ├── 按班级分组统计报名人数
  ├── 验证硬约束（同年级、同性别）
  └── 按报名时间排序（先报先排）

Step 2: 计算组数
  ├── 最大班级人数 = max(各班报名人数)
  ├── 需要组数 = ceil(最大班级人数 / 跑道数)
  └── 确保组数至少为1

Step 3: 按班级报名人数降序排序（大班优先分配）

Step 4: 贪心分配运动员
  ├── For each 班级（按人数降序）:
  │   For each 运动员（按报名时间）:
  │       ├── 选择最优组（同班人数最少的组）
  │       ├── 选择最优跑道（同班未占用的跑道，优先不同的）
  │       └── 分配运动员到该位置
  └── 记录分配历史（用于回滚）

Step 5: 局部优化（可选，按配置）
  ├── 交换相邻组的运动员位置
  ├── 检查同班同跑道冲突
  ├── 同班同学尽量在不同组
  └── 优化同班分散度指标

Step 6: 结果验证
  ├── 验证所有运动员都有位置
  ├── 验证同班同跑道冲突（产生警告）
  ├── 验证同年级一致性
  └── 统计各组人数均衡度

Step 7: 输出结果
  ├── 返回编排结果数据结构
  ├── 生成警告列表
  └── 计算并输出统计信息
```

### 4.6.4 编排示例

**场景**：高一男子100米，8条跑道，共24人报名

| 班级 | 报名人数 | 分配结果 |
|------|:--------:|----------|
| 高一1班 | 3 | 第1组·道1，第2组·道2，第3组·道3 |
| 高一2班 | 3 | 第1组·道2，第2组·道3，第3组·道4 |
| 高一3班 | 3 | 第1组·道3，第2组·道4，第3组·道5 |
| 高一4班 | 3 | 第1组·道4，第2组·道5，第3组·道6 |
| 高一5班 | 3 | 第1组·道5，第2组·道6，第3组·道7 |
| 高一6班 | 3 | 第1组·道6，第2组·道7，第3组·道8 |
| 高一7班 | 3 | 第1组·道7，第2组·道8，第3组·道1 |
| 高一8班 | 3 | 第1组·道8，第2组·道1，第3组·道2 |

**结果**：3组 × 8条跑道，每组8人。同班同学在不同组、不同道次。

### 4.6.5 边界情况处理

| 情况 | 处理方式 |
|------|----------|
| 报名人数 ≤ 跑道数 | 1组，从第1道开始分配 |
| 报名人数不是跑道数倍数 | 最后一组可能不满，从内道开始分配 |
| 同班人数 > 组数 | 同班同组不可避免，产生警告 |
| 单个班级人数 > 总组数×跑道数 | 报错，提示人数超过容量 |
| 硬约束冲突 | 报错，返回具体冲突原因 |

## 4.8 排名与积分模块

### 4.8.1 排名计算规则

1. **按组成绩排序**：每组内按成绩升序排列（径赛时间越短越好）
2. **合并所有组**：将所有组的成绩合并，按成绩升序排列
3. **处理并列**：
   - `same_rank` 模式：成绩相同者并列同一名次，下一名次顺延
   - `sequential` 模式：成绩相同者按报名顺序/学号区分名次
4. **总名次分配**：按合并后的顺序分配总名次

### 4.8.2 积分计算规则

1. **基础积分**：根据总名次查积分表获得
2. **破纪录加分**：如启用且运动员破纪录，额外加分
3. **参与分**：如启用，所有参赛且有效成绩的运动员获得参与分
4. **接力加倍**：接力项目积分乘以配置倍数

### 4.8.3 团体总分计算

按班级（或年级）汇总所有运动员的积分，生成团体总分榜。

# 8. API 接口详细

## 8.1 接口设计规范

### 8.1.1 通用规范

| 规范项 | 说明 |
|--------|------|
| 基础路径 | `/api/v1/` |
| 请求格式 | `application/json` |
| 响应格式 | `application/json` |
| 字符编码 | UTF-8 |
| 时间格式 | ISO 8601 (`YYYY-MM-DDTHH:mm:ssZ`) |
| 分页参数 | `page`（页码，默认1）、`size`（每页条数，默认20） |
| 排序参数 | `sort`（字段名，默认id）、`order`（asc/desc，默认desc） |

### 8.1.2 统一响应格式

**成功响应**：
```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": "2026-07-19T10:30:00Z"
}
```

**分页响应**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "content": [],
    "page": {
      "number": 1,
      "size": 20,
      "totalElements": 100,
      "totalPages": 5
    }
  },
  "timestamp": "2026-07-19T10:30:00Z"
}
```

**错误响应**：
```json
{
  "code": 400,
  "message": "参数验证失败",
  "errors": [
    {
      "field": "name",
      "message": "姓名不能为空"
    }
  ],
  "timestamp": "2026-07-19T10:30:00Z"
}
```

### 8.1.3 HTTP 状态码

| 状态码 | 说明 |
|--------|------|
| 200 | 成功 |
| 201 | 创建成功 |
| 204 | 删除成功（无内容） |
| 400 | 请求参数错误 |
| 401 | 未认证（Token无效/过期） |
| 403 | 无权限（角色不足） |
| 404 | 资源不存在 |
| 409 | 数据冲突（唯一性冲突） |
| 422 | 业务验证失败 |
| 500 | 服务器内部错误 |

### 8.1.4 认证方式

所有 API（除登录/健康检查外）需在请求头中携带 JWT Token：

```
Authorization: Bearer <access_token>
```

## 10.4 Docker Compose 配置

```yaml
# docker-compose.yml
version: '3.8'

services:
  # MySQL 数据库
  mysql:
    image: mysql:8.0
    container_name: sports_mysql
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: sports_meet
      MYSQL_USER: sports_admin
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
      TZ: Asia/Shanghai
    volumes:
      - ./data/mysql:/var/lib/mysql
      - ./backups:/backups
    ports:
      - "3306:3306"
    restart: unless-stopped
    networks:
      - sports_network
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-u", "root", "-p${MYSQL_ROOT_PASSWORD}"]
      interval: 10s
      timeout: 5s
      retries: 5
    profiles:
      - mysql

  # Java 应用
  app:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: sports_app
    environment:
      SPRING_PROFILES_ACTIVE: ${SPRING_PROFILE}
      DB_TYPE: ${DB_TYPE}
      DB_HOST: mysql
      DB_PORT: 3306
      DB_NAME: sports_meet
      DB_USER: sports_admin
      DB_PASSWORD: ${MYSQL_PASSWORD}
      REDIS_HOST: redis
      REDIS_PORT: 6379
      REDIS_PASSWORD: ${REDIS_PASSWORD}
      JWT_SECRET: ${JWT_SECRET}
      TZ: Asia/Shanghai
    volumes:
      - ./data/uploads:/app/uploads
      - ./data/exports:/app/exports
      - ./data/logs:/app/logs
    ports:
      - "8080:8080"
    depends_on:
      mysql:
        condition: service_healthy
    restart: unless-stopped
    networks:
      - sports_network

  # Redis（可选）
  redis:
    image: redis:7-alpine
    container_name: sports_redis
    command: redis-server --appendonly yes --requirepass ${REDIS_PASSWORD}
    volumes:
      - ./data/redis:/data
    ports:
      - "6379:6379"
    restart: unless-stopped
    networks:
      - sports_network
    profiles:
      - full

  # Nginx
  nginx:
    image: nginx:alpine
    container_name: sports_nginx
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./frontend/dist:/usr/share/nginx/html
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf
      - ./nginx/ssl:/etc/nginx/ssl
      - ./data/uploads:/usr/share/nginx/html/uploads
    depends_on:
      - app
    restart: unless-stopped
    networks:
      - sports_network
    profiles:
      - full

networks:
  sports_network:
    driver: bridge
```

## 11.8 数据迁移方案

### 11.8.1 从Excel到系统的迁移流程

```
阶段1：模板准备
  ├── 下载系统标准导入模板
  └── 将现有Excel数据按模板整理

阶段2：试导入
  ├── 选择"预览导入"模式
  ├── 检查列名映射是否正确
  ├── 修正别名映射配置
  └── 查看校验错误并修正原始数据

阶段3：正式导入（按顺序）
  ├── Step 1: 导入班级 → 校验通过
  ├── Step 2: 导入运动员 → 自动关联班级
  ├── Step 3: 导入报名 → 自动校验规则
  └── Step 4: 导入成绩 → 自动计算秒数

阶段4：数据校验
  ├── 导出系统数据与原始Excel交叉比对
  ├── 确认运动员总数一致
  ├── 确认报名人次一致
  └── 确认成绩数据一致
```
