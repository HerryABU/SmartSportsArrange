> 汇总来源：四批评审文件 + `git log` 中散落的问题。

> 状态约定：✅ 已修复 / 🟡 进行中 / ⬜ 待办。

## 一句话总评

这是典型的**单人快速迭代**产物：功能闭环完整、能跑、能交付，但积累了标准的技术债——
少量**真实 bug**（溢出、异常类型、事务边界、安全头）、一批**可维护性隐患**（硬编码、重复解析、
O(n²)、空占位实现），以及三个**上帝类**。本次将问题按严重程度分四级，并**已修复全部高/中优先级的真实缺陷**，
低优先级小隐患与可维护性改造也基本清零；仅余两个超大编排类的结构性拆分，挂起于冒烟门禁开启后再做。

## 🔴 高优先级（影响正确性 / 安全，必须修）

### H1 — 缺乏测试纪律（CI + pre-commit 门禁）
- **根因**：仓库无自动化测试闸门；提交前不跑单测，回归只能靠人工/烟测事后发现。
- **影响**：任何「本地能过、CI 挂」的回归都会溜进主干；违反用户确立的「implement → build → verify → commit」闭环。
- **修复**（本会话）：
  - `.github/workflows/test.yml`：推送/PR 自动 `JDK21 + Maven 缓存 + mvn test`。
  - `.githooks/pre-commit`：提交前跑 `mvn -o test` 拦住明显回归。
  - `scripts/install-git-hooks.sh`：一键安装钩子（**未自动激活**，待用户执行安装，避免本会话每次提交都触发全量单测）。
- **状态**：✅ 配置就绪；完整单测由 CI / 钩子触发（本会话按约定暂不跑重烟测）。

### H2 — `ResultService.parseTimeToSeconds` 返回 `MAX_VALUE`（真实 bug）
- **位置**：`service/ResultService.java`
- **根因**：解析成绩时间失败时返回 `Double.MAX_VALUE`，调用方 `if (result.getTimeSeconds() < recordTime)` 会把**每一个合法成绩**都误判为打破校纪录并加分。且 `MAX_VALUE` 入参求解器有溢出风险（捕获分支从未触发，因为方法吞掉了异常）。
- **影响**：成绩册里大量「假破纪录」，积分错误；潜在数值溢出。
- **修复**（commit `1e9b657`）：改为返回**可空 `Double`**；调用方改为 `recordTime != null && ...` 判定，删除多余 try/catch。
- **状态**：✅ 已修复。已确认 `ScoreDataListener`、`ExcelService` 同类方法本就返回可空 `Double`，仅 `ResultService` 是危险版本。

### H3 — 未登录抛 `RuntimeException` → 500 而非 401
- **位置**：`controller/RefereePortalController.java`（`currentUserId()`）
- **根因**：未取到当前登录用户时 `throw new RuntimeException(...)`，Spring 默认映射为 **500**。
- **影响**：裁判端登录态失效时返回 500，前端无法区分「未登录」与「服务器错误」，登录拦截形同虚设。
- **修复**（commit `9968c02`）：改用 `BusinessException.unauthorized("未登录或登录已过期")` → 返回 **401**。
- **状态**：✅ 已修复。

### H4 — 批量通过/拒绝循环无事务原子性
- **位置**：`controller/RegistrationController.java` + `service/RegistrationService.java`
- **根因**：批量操作在 Controller 层逐个调用，循环体不在同一事务；单条失败无法整体回滚，且缺审计。
- **影响**：批量审批中途失败会留下半成品数据；缺审计痕迹。
- **修复**（commit `fc26f5c`）：`batchApprove` / `batchReject` 下沉到 **Service 单层事务**（`@Transactional`），循环内单条业务失败收集进 `failures`，底层持久化失败整体回滚；空列表守卫返回 `{success:0,...}`。
- **状态**：✅ 已修复。

## 🟡 中优先级（可维护性 / 配置合规）

### M1 — 上帝类拆分
- **根因**：`ScheduleService`(2374)、`ArrangementService`(2247)、`ExcelService`(1017)、`SystemService`(688) 四类承载过多职责。

## 关联背景（避免回归的坑）

- **SQLite 单写者事务回归（M5，前序）**：`AuditService.record` 是 `REQUIRES_NEW`，在外层 `@Transactional` 内直接调用会在 SQLite 下触发 `SQLITE_BUSY → UnexpectedRollbackException`。**新增审计一律走 `TransactionSynchronizationManager.registerSynchronization(afterCommit{...})`**（H4/L9 已按此模式）。
- **构建纪律**：Git Bash `./mvnw` 在本机不可用（classworlds），须经 **PowerShell + 缓存 `mvn.cmd` + `$env:JAVA_HOME`** 构建；`mvn` 离线用 `-o`。
